## 알려진 운영 한계

Firebase Emulator Suite 검증이며 운영 DB/실제 스마트폰 검증은 수행하지 않았다. 방장 브라우저가 끊기면 판정이 멈춘다. 익명 UID 분실 복구·방장 교체·치팅 방지는 없다. 방은 24시간 유효하고 명시적 나가기는 삭제하며 만료/종료 방은 다음 방 생성 시 정리하고, 만료 숫자 코드는 재사용한다. 아무도 접속하지 않을 때 실행되는 주기적 정리는 없다. Firebase 무료 사용량 한도가 있다. Legacy MemoryRoomStore의 재시작/replica 한계는 현재 운영 경로와 무관하다.

최신 추가 검증: 숫자 4자리(앞자리 0 포함) 생성, 활성 코드 충돌 회피, 만료 코드 재사용, 제3자의 활성 방 삭제 차단, 역할별 빈 이름 기본값. 360×740 / 390×844 / 412×915에서 12개월 바닥패와 중앙 덱의 좌표·크기·비중첩을 확인했다. 시작 보너스 2장 연속 획득·보충은 양쪽 선 모두 검증했고, 뻑 보너스가 해당 월 더미에 표시됨을 확인했다. 연결 대기 중 행동 금지와 종료 안내 확인 후 삭제된 방을 재생성하지 않는 경로도 검증했다.

## 전체 점검 — 2026-10-03

추가 시뮬레이션은 seed 1000–3999의 3,000판에서 쉬움/보통/어려움 AI를 섞고 국화 유지/전환을 무작위로 선택했다. 56,882개 행동 모두 엔진의 50장 카드 보존 검사를 통과했고 모든 판이 100개 행동 이내 종료했다. 폭탄 814회, 쪽 821회, 따닥 100회, 쓸 421회, 국화 선택 1,787회를 포함한다. 기존 seed 0–999 단위 테스트까지 합쳐 4,000판을 확인했다. npm audit --omit=dev 기준 알려진 운영 의존성 취약점은 0개다.

코드 점검 후 국화 필수 선택창은 행동 가능 상태에서만 표시하도록 수정했다. 상대가 끊기면 연결 배너와 게임 나가기 조작을 사용할 수 있고, 재접속하면 같은 선택을 이어간다. 방에서 나온 뒤 이전 행동/다음 판 요청의 늦은 실패가 새 화면을 변경하지 않도록 generation 검증을 추가했다. 방 목록 localStorage가 JSON 객체처럼 손상되어도 새 방 생성이 가능하도록 배열/문자열 검증을 추가했다. 개발 룰 검증창이 열렸을 때 컴퓨터가 진행하지 않도록 했다.

운영 한계는 유지된다. 방장 브라우저의 연결이 끊기면 진행은 멈추며 같은 UID로 돌아와야 복구된다. 익명 UID 삭제 후 기존 자리 복구와 자동 방장 교체는 없다. 참가자는 원본 게임 데이터를 읽을 수 있어 가족·친구가 서로 신뢰하는 용도다. 실제 Android 하드웨어 Back, 실제 두 폰의 운영 Firebase 플레이, 음향·진동의 물리적 체감은 자동 검증 대상이 아니다.

전체 점검 최종 검증: 단위 87개, Firebase 에뮬레이터 9개, 기존 브라우저 40개와 추가 접속 중단 회귀 1개, production PWA 2개 통과. TypeScript와 production 빌드도 통과했다. 추가 브라우저 검증은 손상된 방 목록에서도 방 생성 → 국화 필수 선택 → 상대 offline → 선택창 닫힘/나가기 확인 가능 → online → 동일 version 선택창 복원 → 열끗 유지 → 상대 턴 → 방 종료/홈 복귀를 확인한다.

## 이름 조사와 고/스톱 판단 화면

한글 받침에 따라 지훈이/민수가처럼 이·가를 선택한다. 은·는, 을·를, 과·와, 으로·로도 공통 함수에서 처리하고, 의는 고정으로 붙인다. 분해 한글, 숫자와 장식 문자가 붙은 이름을 포함한 단위 검증을 추가했다. 실제 두 브라우저의 친구 이름을 지훈·민수로 설정해 기다리는 사람의 이름이 자연스럽게 표시되는지 검증했다.

고/스톱은 중앙 모달 대신 기존 게임 헤더의 결정 바로 표시한다. 게임판 좌표를 바꾸지 않고 기본점수, 고 횟수, 스톱 정산점수와 배수를 함께 보여준다. 바닥패와 양쪽 획득패를 확대하고 Back으로 돌아와도 고/스톱 단계는 유지된다. 360×740 / 390×844 / 412×915에서 실제 hit test로 모든 손패·바닥패·덱·획득 영역이 가려지지 않는지 확인한다. WebKit의 0.25px 경계 반올림은 좌표 검사에서 1px 이내로 허용한다. Legacy 방 테스트의 총통 초기 승수를 0으로 가정하던 불안정한 검증은 연결 단절 전후의 실제 승수 비교로 수정했다.

이번 변경 검증: 단위 88개 통과, TypeScript와 production 빌드 통과, 브라우저 43개 항목 확인(결정 바 최종 조정 후 양 엔진 해당 검사 재통과), PWA 2개 통과.

## 짧은 인앱 브라우저 화면

일반 안내 문구를 바닥패 영역에서 분리하고 게임판의 고정 최소 높이를 제거했다. 378×672(제보 화면에 대응), 360×640, 390×600에서 손패·바닥패·중앙 덱의 크기를 함께 축소하고 손패 하단 여백을 확보한다. 같은 판을 유지하며 672→640→600→744→672로 리사이즈해 안내/패 및 서로 다른 열두 달 바닥패/중앙 덱의 경계가 겹치지 않는지, 손패 10장 표시, 페이지 스크롤 없음, game version 보존을 Chromium과 WebKit에서 검증한다. 실제 카카오톡 앱의 툴바·기기 확대 설정은 실기기 확인 항목이다.

검증 결과: 단위 88개, 타입 검사, production 빌드, PWA 2개 통과. 전체 브라우저 검사에서 기존 항목 43개와 WebKit 새 항목이 통과했으며, Chromium의 리사이즈 적용 대기를 보완한 최종 새 검사를 두 브라우저에서 각각 3회 반복 통과했다. 총 E2E 항목은 45개다.
